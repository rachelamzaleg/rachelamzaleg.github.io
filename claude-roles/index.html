QA + Claude

Give Claude a Role

I get better results when Claude has one clear job instead of drafting, checking and documenting everything in the same step.

One task, one role

I separate the work so each pass has a clear purpose.

QA TesterBuilds the first test approach from the requirements and evidence.
ValidatorLooks for gaps, assumptions, contradictions and missing coverage.
DocumentationTurns a verified result into a clean runbook or reusable note.
StatusSummarizes what is done, blocked or still open without redesigning the work.

Why separate them?

If the same Claude draft also "reviews" its own answer immediately, it can easily repeat the same assumptions. A separate validation pass gives the review a narrower job.

Draft → Validate → Fix → Document

Use validation selectively

Not every small task needs several passes. I use the extra review when the work is important enough to justify it: test plans, risky changes, complex investigations or reusable team material.

Real QA Example

Separate planning from validation

For a complex change, I first used AI to draft a focused validation approach from the available requirements and technical context. Instead of accepting that first output, I ran a separate validator pass with one job: challenge assumptions, look for missing integration paths and identify unanswered questions.

The second pass surfaced gaps that were easy to miss when drafting and reviewing were mixed together. I then updated the test approach before execution, using AI as a structured review aid rather than as the decision maker.

Try a validator pass

Act only as the validator for the QA work below.

Do not rewrite the whole plan.
Check for:
- missing coverage
- unsupported assumptions
- contradictions with the evidence
- important negative or edge cases
- questions that must be answered before execution

Return only:
1. gaps
2. risks
3. questions
Do not ask one Claude pass to do every job.
