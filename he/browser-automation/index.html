בודקים פעם אחת. אחר כך מריצים סקריפט.

כך משאירים את Claude למשימות שצריכות חשיבה, ולא מבזבזים טוקנים על פעולות דפדפן שחוזרות על עצמן.

קודם בוחרים את הדרך הפשוטה

קודם API: אם למוצר יש API שמתאים למשימה, משתמשים בו.
אחר כך סקריפט שמור: מריצים בדיקת Playwright שכבר נבדקה.
רק כשצריך דפדפן ידני: מבקשים אישור לפני עבודה אינטראקטיבית.

הופכים בדיקה ידנית לסקריפט

אחרי שהתרחיש עובד, שומרים אותו כסקריפט שאפשר להריץ שוב. פעולות קבועות אחרי הרצה אפשר לבצע בסקריפט נוסף, בלי להעמיס כל פעם את מצב הדפדפן על Claude.

משתמשים ב־Hooks כדי לשמור על כללים

Hooks מפעילים בדיקות וכללים בשלבים קבועים בתהליך. הסקריפטים מבצעים את העבודה החוזרת, ו־Claude נשאר לניתוח של תוצאות לא צפויות.

כמה Context זה יכול לחסוך?

~2,000טוקנים לשמונה משימות שמורות
~16,000טוקנים ל־Snapshot אחד שנכנס ל־Context

אלה מספרים לדוגמה משני סוגי עבודה שונים, לא השוואה מדויקת של אותה משימה.

עדיין צריך לבדוק את התוצאות

שומרים ממצאים ולוגים, בודקים כישלונות ומשתמשים ב־AI כשצריך להבין התנהגות חריגה. כדי להציג אחוז חיסכון, צריך למדוד את אותה משימה בשתי דרכים.

העיקרון: מה שסקריפט יכול לעשות לבד — נותנים לו לעשות. את ה־AI שומרים לניתוח ולשיקול דעת.

רוצים ליישם? העתיקו את הפרומפט

פרומפט מוכן שאפשר להתאים למשימה שלכם.

בחירת פתרון יעיל לבדיקות דפדפן

בקש ממני תיאור של בדיקת דפדפן חוזרת. בדוק קודם אפשרות ל־API או סקריפט קיים. אם דרוש UI, תכנן בדיקת Playwright עם Assertions, לוגים ותנאי עצירה. אל תמציא נתוני חיסכון.

שאל שאלות ממוקדות, אל תמציא ממצאים, והצע צעד אחד בכל פעם.

ביצוע בפועל: כשיש לך גישה לכלים מתאימים, בצע בעצמך בדיקות קריאה בטוחות, הרצת סקריפטי בדיקה קיימים, קריאות API ובדיקות לוגים ומסד נתונים לפי הצורך. הצג בדיוק מה הורץ ומה התקבל, והתקדם לפי התוצאות. אם אין גישה לכלי, ציין זאת והכן בדיקה שאוכל להריץ. בקש אישור לפני שינוי נתונים או הגדרות, פעולות בעלות השפעה או בדיקות ב־Production. לעולם אל תציג בדיקה שלא בוצעה כאילו בוצעה.

Playwright ושימוש חוזר: אם השתמשת ב־Playwright לחקירה אינטראקטיבית או לבדיקת תרחיש שחוזר, לאחר שהתרחיש אומת בחן אם כדאי להפוך אותו לטאסק מבוסס סקריפט לשימוש עתידי. העדף סקריפט Playwright יציב עם קלטים מוגדרים, Assertions, לוגים, טיפול בכשלים ופקודת הרצה קצרה, במקום לחזור בכל הרצה על ניווט אינטראקטיבי וקריאת מצב הדפדפן באמצעות AI. שמור את הסקריפט ואת הוראות ההרצה במקום מתאים רק לאחר אישורי. בהרצות הבאות השתמש בסקריפט הקיים, והפעל חקירה אינטראקטיבית רק אם הוא נכשל או שהתרחיש השתנה. המטרה היא לצמצם עבודה חוזרת ושימוש מיותר בטוקנים; אל תטען לחיסכון מספרי בלי מדידה.
