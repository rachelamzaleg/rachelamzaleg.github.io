בודקים פעם אחת. אחר כך מריצים סקריפט.

כך משאירים את Claude למשימות שצריכות חשיבה, ולא מבזבזים טוקנים על פעולות דפדפן שחוזרות על עצמן.

קודם בוחרים את הדרך הפשוטה

קודם API: אם למוצר יש API שמתאים למשימה, משתמשים בו.
אחר כך סקריפט שמור: מריצים בדיקת Playwright שכבר נבדקה.
רק כשצריך דפדפן ידני: מבקשים אישור לפני עבודה אינטראקטיבית.

הופכים בדיקה ידנית לסקריפט

אחרי שהתרחיש עובד, שומרים אותו כסקריפט שאפשר להריץ שוב. פעולות קבועות אחרי הרצה אפשר לבצע בסקריפט נוסף, בלי להעמיס כל פעם את מצב הדפדפן על Claude.

משתמשים ב־Hooks כדי לשמור על כללים

Hooks מפעילים בדיקות וכללים בשלבים קבועים בתהליך. הסקריפטים מבצעים את העבודה החוזרת, ו־Claude נשאר לניתוח של תוצאות לא צפויות.

כמה Context זה יכול לחסוך?

~2,000טוקנים לשמונה משימות שמורות
~16,000טוקנים ל־Snapshot אחד שנכנס ל־Context

אלה מספרים לדוגמה משני סוגי עבודה שונים, לא השוואה מדויקת של אותה משימה.

עדיין צריך לבדוק את התוצאות

שומרים ממצאים ולוגים, בודקים כישלונות ומשתמשים ב־AI כשצריך להבין התנהגות חריגה. כדי להציג אחוז חיסכון, צריך למדוד את אותה משימה בשתי דרכים.

העיקרון: מה שסקריפט יכול לעשות לבד — נותנים לו לעשות. את ה־AI שומרים לניתוח ולשיקול דעת.
