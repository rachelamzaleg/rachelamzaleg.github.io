פעולות גלישה חוזרות על עצמן? Claude צריך לזהות את זה

תוך כדי העבודה Claude מזהה רצפי פעולות חוזרים, בודק אם קיים API או סקריפט מתאים, והופך תהליך מאומת לטאסק שאפשר להריץ שוב.

קודם בוחרים את הדרך הפשוטה

קודם API: אם למוצר יש API שמתאים למשימה, משתמשים בו.
אחר כך סקריפט שמור: מריצים בדיקת Playwright שכבר נבדקה.
רק כשצריך דפדפן ידני: מבקשים אישור לפני עבודה אינטראקטיבית.

הופכים בדיקה ידנית לסקריפט

אחרי שהתרחיש עובד, שומרים אותו כסקריפט שאפשר להריץ שוב. פעולות קבועות אחרי הרצה אפשר לבצע בסקריפט נוסף, בלי להעמיס כל פעם את מצב הדפדפן על Claude.

משתמשים ב־Hooks כדי לשמור על כללים

Hooks מפעילים בדיקות וכללים בשלבים קבועים בתהליך. הסקריפטים מבצעים את העבודה החוזרת, ו־Claude נשאר לניתוח של תוצאות לא צפויות.

כמה Context זה יכול לחסוך?

~2,000טוקנים לשמונה משימות שמורות
~16,000טוקנים ל־Snapshot אחד שנכנס ל־Context

אלה מספרים לדוגמה משני סוגי עבודה שונים, לא השוואה מדויקת של אותה משימה.

עדיין צריך לבדוק את התוצאות

שומרים ממצאים ולוגים, בודקים כישלונות ומשתמשים ב־AI כשצריך להבין התנהגות חריגה. כדי להציג אחוז חיסכון, צריך למדוד את אותה משימה בשתי דרכים.

העיקרון: מה שסקריפט יכול לעשות לבד — נותנים לו לעשות. את ה־AI שומרים לניתוח ולשיקול דעת.

רוצים ליישם? העתיקו את הפרומפט

פרומפט מוכן שאפשר להתאים למשימה שלכם.

כלל עבודה קבוע: זיהוי אוטומטי של פעולות חוזרות ושימוש חוזר בסקריפטים

במהלך כל משימת QA שאתה מבצע, שים לב לרצפי פעולות בדפדפן שחוזרים על עצמם או צפויים לשמש שוב. אל תחכה שאבקש ממך לזהות אותם, ואל תבקש ממני לתאר מראש בדיקה חוזרת.

פעל לפי הסדר:
1. בצע את המשימה הנוכחית באמצעות הכלים המורשים הזמינים לך.
2. לפני ניווט אינטראקטיבי חוזר, בדוק אם API או סקריפט קיים יכולים לבצע את הפעולה בצורה אמינה ופשוטה יותר.
3. אם נדרשת חקירה ב־Playwright, בצע אותה ואמת את התוצאה בפועל.
4. כשאתה מזהה רצף יציב בעל ערך לשימוש חוזר, הצע להפוך אותו לטאסק מבוסס סקריפט. הסבר בקצרה מה יישמר ומה ירוויח התהליך. אל תייצר סקריפט לכל פעולה חד־פעמית.
5. לאחר אישור, צור סקריפט Playwright עם קלטים ברורים, Assertions, טיפול בכשלים, לוגים ופקודת הרצה קצרה. שמור אותו עם הוראות שימוש.
6. במשימות הבאות העדף את הסקריפט הקיים. חזור לחקירה אינטראקטיבית רק כשהתרחיש משתנה, הסקריפט נכשל או יש ממצא חדש.

אם הכלים זמינים לך, בצע בדיקות קריאה בטוחות בפועל והצג מה הורץ ומה התקבל. אם אין לך גישה, אמור זאת והכן דרך הרצה למשתמש. בקש אישור לפני פעולות המשנות נתונים או הגדרות, בדיקות Production או פעולות בעלות השפעה. אל תציג בדיקה שלא בוצעה כאילו בוצעה, ואל תטען לחיסכון מספרי בטוקנים ללא מדידה.
