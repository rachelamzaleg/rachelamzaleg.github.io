QA + Claude · Context Efficiency

One Fact, One Home

Reduce repeated context, keep changing facts at their source and make QA workflows reusable.

1. Give each fact a home

Workspace rules → common conventions
Skills → repeatable procedures
References → product facts
Ticket notes → task evidence
Live tracker → current status

2. Retrieve selectively

Read relevant file sections and targeted logs rather than whole histories. Query the live source for changing data.

3. Remove stale copies

When an instruction changes, update its original location and remove duplicates. A long project instruction file with outdated rules is not a better source of context.

4. Work with a context budget

Start with the smallest useful input: the relevant requirement, one reproducible failure and the few logs or queries that explain it. Expand only when the evidence calls for more.

Keep project rules short → put only always-applicable instructions in the project file.
Load skills on demand → attach the procedure needed for this specific task, not every procedure.
Delegate narrow investigations → return concise findings and evidence, rather than full exploratory transcripts.
Save a verified handoff → record commands, results and unresolved questions before a long session becomes unwieldy.

5. Move repeatable test work out of Claude

A practical QA automation pattern uses Playwright for test execution, hooks for integration with the test workflow, and a post-run script for recurring work after execution. Tasks that can be performed deterministically by a script need not be repeatedly delegated to an AI conversation.

Playwright execution → Hooks → Post-run script → QA investigation when needed

Use hooks to enforce workflow guardrails and post-run scripts to handle repeatable results processing. Reserve interactive AI work for analysis that needs judgment.

6. Measure what actually helps

For a meaningful token comparison, measure the same task performed in different ways and verify the output quality. Track execution time and repeatability alongside token usage.

Automate predictable actions with scripts. Use AI where investigation and judgment add value.
Applied pattern · Browser QA

Explore once. Run the script again.

Repeated interactive browser exploration can be expensive in AI context. For recurring UI checks, use a more deliberate sequence:

API first → use product APIs when they cover the task.
Explore once → when browser interaction is essential, validate the flow and save it as a reusable Playwright script.
Run the script → let saved tasks and post-run processing handle repeatable operations; use hooks as workflow guardrails.
Escalate selectively → ask for approval before hand-driving the browser; use Claude for failures that require reasoning.
