Make Every Correction Reusable

The QA task produces a result. A useful correction can improve how the next QA task is performed.

The improvement loop

  1. Spot the failureA repeated mistake exposes a gap in the process.
  2. Correct the causeFix the procedure, not only the latest output.
  3. Choose one homePlace the lesson where future work needs it.
  4. Verify & keepReview the new rule and commit at a milestone.

Keep context clean

Workspace instructions hold broad conventions. Skills hold repeatable procedures. References hold product facts. Ticket notes hold task-specific findings. Live tracker status stays in the tracker—not in a copied status file.

I retrieve only the sections, logs and source data needed for the current question, instead of carrying entire histories into every AI session.

A practical example

If an assistant works around a failed setup step, fixing one report is not enough. I update the setup skill to stop at that checkpoint, capture the exact failure and request direction. The next run starts with a better procedure.
